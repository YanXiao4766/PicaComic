# nhentai 热门榜历史归档与日期浏览需求

版本：v0.4 需求与实现记录

日期：2026-10-29

范围：需求、交互设计、功能实现与本地验证。Android 打包与真机联网验收状态见第 10 节。

## 1. 目标与已确认需求

在 nhentai 的中文、日本语、英文分类子页面中，按日期回看曾经采集的热门漫画榜单。

| 项目 | 需求 | 状态 |
| --- | --- | --- |
| 页面入口 | 保留现有五种排序：最近、热门｜今天、热门｜一周、热门｜本月、热门｜所有时间 | 用户提出 |
| 日期控件 | 页面右下角增加「上一天 / 月日 / 下一天」；点击月日打开日历 | 用户提出 |
| 日历 | 展示完整年月日；有数据的日期有底色，无数据日期呈灰色；提供立即返回当天 | 用户提出 |
| 自动采集 | 启动先检查当天本地记录；只自动补采缺失或不完整的榜单，每榜前 100 个编号 | **用户最新确认** |
| 语言范围 | 中文、日本语、英文分别保存，每天合计 9 份榜单、最多 900 个编号位置 | **用户已确认** |
| 历史列表 | 切换日期后，读取该日期、语言与榜单对应的编号，显示漫画列表 | 用户提出 |
| 同日更新 | 自动采集跳过当天已有完整记录；右上角手动更新可重新采集并覆盖，失败保留旧成功版本 | **用户最新确认** |
| 辅助缓存 | 编号为核心，允许独立缓存标题和封面地址；图片沿用现有缓存 | **用户已确认** |
| 日历手势 | 上下滑动切换月份，左右滑动切换年份 | **用户新增** |
| 跳页按钮位置 | 保留现有跳页按钮，放在日期控件上方 | **用户新增** |

900 是榜单位置数。同一编号可以出现在不同榜单中，不应跨榜单去重。

## 2. 日期和榜单的含义

**日期代表实际采集日期，不代表漫画发布时间。**

例如选择「2026-10-28 / 中文 / 热门｜一周」，显示的是 10 月 28 日采集时网站“一周热门”的前 100 个编号，保持当时的顺序。它不是在本地统计 10 月 28 日所在自然周的热度。

- 三个热门榜直接使用来源站点的排序结果，不在本地重新计算热度。
- 归档只从功能启用并首次成功采集后开始积累。
- 没有采集的过去日期显示无记录。现有代码没有历史榜单查询能力，不能承诺补回过去的排名。
- App 关闭期间不承诺采集；常驻后台、定时唤醒和云端采集不纳入首版。
- 建议以设备本地日期分组。日期键包含年份，采集时间另外保存时区偏移。
- 跨午夜时，每份榜单以采集开始时的日期归档；不同榜单可以分别落在相邻两天。界面展示各自的采集时间。

## 3. 页面交互

### 3.1 默认页面

- 进入三个语言子页面时，默认选中当天；排序默认沿用现有逻辑。
- 三个热门榜在选中当天时使用原来的在线加载与分页，不受归档 100 项上限限制；只有过去日期读取归档，最多 100 项。
- 当天状态显示「实时列表 · 今天 · 在线分页加载」；历史日期显示归档数量与采集时间。
- 浏览过去日期时显示「历史记录」提示，防止误认为当前实时榜单。
- 切换语言或三个热门榜时保留选中日期；当天在线加载，过去日期读取相应记录。
- 打开漫画沿用现有详情页与阅读流程；返回列表时保留日期、排序和滚动位置。

### 3.2 右下角日期控件

建议使用一个分为三个点击区域的圆角控件：`〈   10/29   〉`。

| 操作 | 行为 |
| --- | --- |
| 点击左侧 | 切换到前一个自然日，跨月、跨年自动处理 |
| 点击中间 | 打开日历，顶部显示完整选中日期 |
| 点击右侧 | 切换到后一个自然日；当天的右侧按钮禁用 |
| 遇到无记录日期 | 保持该日期并展示空状态，不偷偷跳到其他日期 |
| 页面滚动 | 控件保持在页面右下角，列表底部预留空间，避免最后一项被遮挡 |

首版建议按自然日切换，符合“上一天、下一天”的含义。若以后需要跳到最近有记录的日期，可作为独立操作增加。

手机需避开系统底部手势区域；桌面采用同一组操作，适配鼠标与键盘。按钮有效触控区域不小于 48×48 逻辑像素，不能仅靠颜色表达禁用状态。

#### 跳页按钮与日期控件共存

- 右下角由上到下排列「现有跳页按钮」和「上一天 / 月日 / 下一天」，两者右边缘对齐，间距建议 12 逻辑像素。
- 跳页按钮保留当前页 / 总页数的显示与输入页码交互，不改变日期；当天使用网站原始页数，过去日期使用本地归档页数。
- 归档列表的总页数依据该份归档实际数量与列表分页大小计算，不能沿用网站实时榜单的总页数。草图仅以每页 20 项、100 项共 5 页演示，不锁定正式实现的分页大小。
- 切换日期、语言或榜单后回到该列表第一页；从漫画详情返回时仍恢复原页码与滚动位置。
- 无归档或当前可见项为零时，跳页按钮禁用，不显示无意义的可跳页范围。
- 「最近」与「所有时间」没有日期控件时，跳页按钮恢复现有右下角位置与在线分页行为。
- 两个控件统一布局和预留空间，不能各自固定到同一个右下角而互相覆盖。列表可滚动到最后一项完整露出。

### 3.3 日期选择日历

手机采用底部弹层；桌面采用居中日期对话框。日历基于**当前语言 + 当前热门榜**判断是否有记录。

| 日期状态 | 建议样式与操作 |
| --- | --- |
| 已有完整归档 | 浅主题色底 + 小圆点，可点击 |
| 仅采集到部分编号 | 浅主题色底 + 三角标记，可点击，选中后说明「部分记录 X/100」 |
| 过去日期，无记录 | 灰色背景与文字；仍可点击，列表显示明确空状态 |
| 未来日期 | 灰色并禁用，不允许选择 |
| 今天 | 日期数字下划线标记；其数据状态仍按上述规则显示 |
| 当前选择 | 深主题色底 + 高对比度文字，完整日期另行显示 |

- 顶部显示完整日期，例如「2026 年 10 月 29 日」。
- 年、月可快速选择，也能通过左右按钮逐月切换；周一作为第一列。
- **日历网格内上滑：下一个月；下滑：上一个月。左滑：下一年；右滑：上一年。** 跨年翻月自动处理；翻年尽量保持月份，超过当前年月时停在当前年月。
- 滑动只改变正在浏览的年月，不立即修改已选日期，也不触发列表加载；点选具体日期后才提交。
- 手势仅作用于日历网格，不作用于弹层拖动柄、年份 / 月份下拉框、底部按钮或遮罩。上下翻月不能同时触发关闭弹层。
- 每次手势只切换一个月或一年；按主方向识别，设置最小距离，避免斜滑误判或滑动后误选日期。到当前年月后不能继续翻向未来。
- 桌面保留按钮与年月选择器；草图同时支持网格内滚轮上下翻月、触控板横向滚动翻年，作为手势操作的补充。
- 点击允许选择的日期后立即切换列表并关闭日历；取消或点遮罩关闭时保持原日期。
- 底部保留醒目的「返回今天」按钮：点击后立即选择当天并关闭日历。
- 返回今天即使当天尚无记录，也必须可用；立即恢复在线列表，归档采集独立执行且只补缺失。在线失败不自动切换为当天归档。
- 日历附简短图例：「有记录 / 部分记录 / 无记录」，辅助区分颜色含义。

### 3.4 最近与所有时间

这两种排序不在自动归档范围内。建议在它们下方显示「实时列表，不支持日期回看」，隐藏日期控件，继续使用现有在线分页。

临时切到这两种排序时保留上次选中的归档日期；切回三个热门榜后恢复。不要用选中历史日期搭配实时内容，以免产生误解。

## 4. 自动采集规则

### 4.1 触发与调度

1. 启动后，在基础初始化、Cookie 与代理配置就绪、主界面可用后，先检查当天本地归档。
2. 按三种语言 × 三个热门榜分别检查：完整记录直接跳过；只为缺失或不完整记录创建任务。九份齐全时不采集，也不探测站点；无需先打开 nhentai 页面。
3. 网络连接不等于站点可访问。通过实际请求判断成功，超时、验证页和解析异常均不能标成采集成功。
4. 断网可读取过去日期的本地归档；当天在线列表沿用加载失败提示。App 在前台恢复联网时，只补采缺失或未完成的当日任务。
5. App 从后台返回前台或日期变化时，仍先检查当天记录；已完整保存的榜单不重复采集。
6. 单次失败建议自动重试最多 2 次并退避；达到上限后等待下一次启动、联网恢复或用户手动重试。
7. 相同「日期 + 语言 + 榜单」同时只运行一个任务，反复进入页面不会重复创建。

自动采集不阻塞启动，不抢占用户正在打开漫画的请求。建议最多 2 个榜单任务并发，每榜逐页请求；最终阈值根据实际站点行为调整。

每次打开先检查本地，而不是必定采集。只有右上角「手动更新今日榜单」会主动重新采集当天已有记录；该操作同时刷新当前在线列表。采集中禁用重复点击。

### 4.2 前 100 项的获取

- 从第一页开始，按照来源返回顺序翻页，收集 100 个有效且不重复的编号后停止。
- 不能假定一页刚好 100 项，也不写死来源每页数量。
- 同一榜单内遇到重复编号时保留首次位置，继续向后补足。
- 来源确实不足 100 项且已确认到末页时，保存实际数量并标为完整、已到末页。
- 翻页中断仅获得 60 项时，不能标成“完整 100 项”。
- 解析为空但无法确认是有效末页时，应记为失败，避免把验证码或结构变化误当空榜单。
- 榜单翻页期间来源可能变化；仅保证本次按序采集的结果，不承诺来源端同一瞬间的一致快照。

### 4.3 同日更新与失败保护（已确认）

一天每榜保留一份成功记录，不增加时间选择器。自动采集不会覆盖已有完整记录；用户手动更新成功后，使用本次结果覆盖。

| 情况 | 保存与展示 |
| --- | --- |
| 启动时当天已有成功记录 | 跳过，不重新采集、不覆盖 |
| 手动更新成功 | 完整写入新版本后再替换，更新采集时间 |
| 已有成功记录，本次失败或仅获取部分 | 保留上次成功版本，显示最近更新未成功 |
| 首次采集只获得部分数据 | 单独保存为部分记录，明确数量，允许回看与重试 |
| 首次采集完全失败 | 保存失败状态，不生成“有归档”标记 |
| 9 份中有一份失败 | 其他成功榜单正常保留，只补失败任务 |
| 写入中途 App 退出 | 不损坏此前已提交的数据，下次继续补采 |

只有手动更新成功时替换同日较早版本；失败或部分结果不能替换已有完整版本。即使上一次手动更新失败，只要旧完整记录仍在，后续自动检查也应跳过。

## 5. 编号存储与列表恢复

### 5.1 归档内容

每份记录至少包含：

| 字段 | 用途 |
| --- | --- |
| schemaVersion | 将来升级存储格式 |
| date | 完整日期，例如 2026-10-29 |
| language | chinese / japanese / english |
| ranking | popular-today / popular-week / popular-month |
| startedAt、capturedAt、timezoneOffset | 采集开始、结束时间与日期口径 |
| ids | **有序编号数组**，位置即原始榜单顺序 |
| actualCount、targetCount | 实际数量与目标 100 |
| status、reachedEnd | 完整、部分、失败与是否到末页 |
| lastAttemptAt、lastError | 最近尝试状态；失败不能覆盖旧归档 |

唯一归档键为「完整日期 + 语言 + 榜单」。编号以字符串保存，避免改变编号格式。

### 5.2 标题和封面缓存（已确认）

编号足以定位漫画，但列表还需要标题和封面。已确认采用「有序编号归档 + 独立简介缓存」：采集榜单时顺带保存已有标题和封面地址，跨榜单按编号共用缓存。语言与标签可复用现有简介模型，以支持正常显示与屏蔽规则。

独立简介缓存不保存整本漫画，不预先下载阅读图片。封面地址不等于封面文件；离线时仅能显示已有图片缓存，缺失时显示占位图。

- 根据编号逐批恢复可见区域附近的简介，避免一次请求 100 个详情。
- 列表按归档编号顺序显示，不能随请求完成顺序重排。
- 切换日期时取消旧页面请求，或校验当前页面标识，防止旧结果覆盖新日期。
- 编号已失效时保留原位置，显示「该漫画暂不可访问」与编号，不自动删除历史记录。
- 用户当前屏蔽设置可继续隐藏内容；显示「归档 X 项，当前可见 Y 项」。归档编号本身不受屏蔽设置改变。
- 切换历史日期只读取对应归档；联网仅用于恢复简介、封面与详情，不以当前热门榜覆盖历史列表。

### 5.3 保存位置与保留策略

建议保存在应用数据目录的独立归档存储中，与可清理的图片缓存分开。可以复用项目已有数据库能力或采用支持原子替换的本地文件，实际实现再确定。

首版建议持续保留，不按 30 天或 90 天自动删除；手动清理时需要明确确认。普通“清图片缓存”不能连带删除榜单编号。

首版只做本机归档；WebDAV 同步、导入导出和跨设备合并暂不纳入。卸载或清除应用数据后不承诺保留。

## 6. 空状态与异常提示

| 场景 | 用户看到的结果 |
| --- | --- |
| 某天从未采集 | 「这一天没有保存的榜单」；可打开日历或返回今天 |
| 今天还在采集 | 显示旧的当日记录或占位状态；提示「正在保存今日榜单」 |
| 今天断网且无归档 | 「今天还没有记录，联网后自动采集」 |
| 有网但站点不可访问 | 提示访问失败，提供重试；不伪装为无漫画 |
| 站点要求验证 | 提示需要完成站点验证；沿用现有验证入口，不能启动时循环弹窗 |
| 某榜仅采到一部分 | 展示已保存项，提示「部分记录 60/100，可重试」 |
| 离线读取历史 | 已存编号正常展示；简介和封面按本地缓存情况显示 |
| 现有屏蔽规则隐藏全部内容 | 提示「已归档 X 项，全部被当前屏蔽规则隐藏」 |

自动采集状态建议放在列表状态行；详细失败信息按需展开，不连续弹出 9 个通知。

## 7. 首版验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 当天无归档，有网冷启动，未进入 nhentai | 三种语言 × 三个热门榜自动采集；来源足够时每份为 100 个有序唯一编号 |
| A2 | 重启 App | 已保存记录可读，编号、顺序、语言、榜单与日期均不串档 |
| A3 | 切换到昨天与跨月日期 | 精确读取对应日期记录，主控件只显示月日，日历显示年份 |
| A4 | 同一日期切换语言、榜单 | 日期保持不变，列表和日历有数据标记同步变化 |
| A5 | 打开日历 | 有归档、部分归档、无记录、选中日期和今天均可区分；未来日期不可选 |
| A6 | 点击返回今天 | 立即选择本地今天并关闭弹层；无归档时仍能返回 |
| A7 | 上一天与下一天 | 按自然日切换；到当天后下一天禁用；无记录日显示空状态 |
| A8 | 获取第 2 页时断网 | 旧成功归档保持完整；首次采集仅存部分并明确标识，不冒充完整 |
| A9 | 断网启动后恢复联网 | 历史先可读，前台联网恢复后自动补采当天，不无限重试 |
| A10 | 快速连续切换日期 | 旧请求不能覆盖新日期列表；排序仍按所选归档顺序 |
| A11 | 切换最近、所有时间 | 保持现有实时分页，不显示会误导用户的历史日期控件 |
| A12 | 清理图片缓存 | 编号归档仍在，缺失封面显示占位或重新联网获取 |
| A13 | 来源不足 100 项、编号失效或被屏蔽 | 正确显示实际数量、占位或可见数量，不悄悄更改归档顺序 |
| A14 | 采集时跨午夜或从后台跨日恢复 | 按定义归档日期，不把前一天数据标为今天；跨日前台恢复触发新任务 |
| A15 | 日历网格上下滑动 | 上滑下一月、下滑上一月，跨年正确；浏览年月变化但选中日期不变 |
