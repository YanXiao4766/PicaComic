以采集日期保存热门榜编号，切换日历回看当时的列表。

## A 已确认的采集范围

| 语言 | 保存的榜单 | 每榜上限 |
| --- | --- | --- |
| 中文 | 今天热门、一周热门、本月热门 | 100 个编号 |
| 日本语 | 今天热门、一周热门、本月热门 | 100 个编号 |
| 英文 | 今天热门、一周热门、本月热门 | 100 个编号 |

每天共 9 份榜单，最多 900 个编号位置。不同榜单可以包含相同编号。

## B 怎样操作日期

| 控件 | 行为 |
| --- | --- |
| 右下角左按钮 | 前一个自然日 |
| 右下角中间 10/29 | 打开日历，显示完整年月日 |
| 右下角右按钮 | 后一个自然日；当天禁用 |
| 日历中的返回今天 | 立即切回当天并关闭日历 |
| 浅色底加圆点 | 当前语言、当前榜单已有归档 |
| 浅色底加三角 | 仅有部分记录 |
| 灰色日期 | 没有归档；未来日期禁用 |
| 日历网格上滑 / 下滑 | 下一月 / 上一月 |
| 日历网格左滑 / 右滑 | 下一年 / 上一年 |
| 日期控件上方的跳页按钮 | 保留页码输入，只在当前列表内跳页 |

建议仅在三个热门榜显示日期控件。最近和所有时间继续使用实时列表。

选中当天时恢复原来的在线加载与分页。只有过去日期读取归档，最多 100 项。

跳页按钮与日期控件右侧对齐，间隔建议 12 像素。滑动只浏览年月，点选日期才切换列表。

## C 哪些日期可以回看

```callout warn 历史从成功采集后积累
日期表示采集当天看到的榜单。未采集的过去日期显示无记录。
当前代码没有查询历史榜单的能力。App 关闭期间的定时采集不在首版范围。
```

选择 10 月 28 日与一周热门，读取当天保存的榜单顺序。

## D 启动后如何归档

```flow
(启动 App) -> 检查当天本地记录
检查当天本地记录 -> {本榜已有完整记录?}
{本榜已有完整记录?} -> 跳过采集: 是
{本榜已有完整记录?} -> 联网补采此榜: 否
联网补采此榜 -> {本榜采集成功?}
{本榜采集成功?} -> 保存有序编号: 是
{本榜采集成功?} -> 保留旧成功记录: 否
保存有序编号 -> 过去日期可回看
```

当天列表在线加载。自动采集只补缺失；已有记录不重复请求。

## E 建议采用的保存规则

| 项目 | 建议 |
| --- | --- |
| 同日重复启动 | 先检查记录，已有完整数据就跳过 |
| 右上角手动更新 | 刷新在线列表，重新采集并更新当天归档 |
| 归档核心 | 日期、语言、榜单、有序编号和采集状态 |
| 辅助缓存 | 独立缓存标题和封面地址，图片沿用现有缓存 |
| 排名恢复 | 始终按归档顺序显示，不随请求完成顺序重排 |
| 保存期限 | 持续保留，普通图片缓存清理不删除编号 |
| 本地日期 | 使用设备本地日期，同时记录采集时区 |

编号失效时保留占位。来源不足 100 项时保存实际数量。

## F 本轮已确认与新增

| 决定 | 规则 |
| --- | --- |
| 同日记录 | 自动不重复采集；手动更新成功后覆盖，失败保留旧记录 |
| 列表简介 | 允许缓存标题与封面地址，编号仍是归档核心 |
| 日历滑动 | 纵向翻月，横向翻年；不改变当前选中日期 |
| 跳页位置 | 现有按钮放在日期控件上方 |

翻月和翻年到当前年月停止。上下滑动只作用于日历网格，不关闭弹层。
